# 墨序 · Markdown 题解编辑器

面向算法题解的 Markdown 编辑器：左侧源码、右侧 KaTeX 实时预览，并内置「题解规范检查」
（全角标点 / 句末句号 / 中英空格 / 公式规范 / 公式语法）。

## 不安装 npm 的使用方式（推荐）

你不需要在自己的电脑安装 Node.js 或 npm。把本项目文件上传到 GitHub 仓库，仓库内的
`.github/workflows/pages.yml` 会在 GitHub 云端自动安装依赖、构建单文件网页并发布到 GitHub Pages。
具体步骤见 `NO-NPM-使用说明.txt`。部署完成后直接通过浏览器网址使用。

开发者如需在本地参与开发，才需要 Node.js 22：

```bash
npm ci
npm run dev
npm run build      # 生成单文件 dist/index.html
npm test
npm run typecheck
```

### 4. 顺手修掉的隐藏 bug

1. 预览字号变量 `--pfs` 从未被赋值，字号按钮只影响源码区 —— 现在两边同步。
2. 叠层高亮给标题加了 `font-weight:500`，字宽变化会让高亮与透明文本框错位 —— 已移除字重/字号类样式。
3. 叠层只同步 `scrollTop`，不同步 `scrollLeft`，横向滚动会错位 —— 已同步。
4. 敲字后 150ms 内预览不跟随滚动（`caretTs` 误判）—— 拆成独立的 caret 滚动时间戳。
5. `onRendered` 依赖光标状态而变化，导致每次移动光标都重刷预览 `innerHTML`（丢复制按钮状态、卡顿）—— 改用 ref 读取。
6. 中文输入法组字时按回车 / Tab / 快捷键会误触发命令 —— 增加 `isComposing` 守卫。
7. `Ctrl+/` 同时被编辑器与全局监听处理，导致帮助弹窗开了又关 —— 全局监听跳过 `defaultPrevented`。
8. 预览里点击外链会把整个应用导航走 —— 改为新窗口打开。
9. 复制按钮用 `btn.textContent` 直接改写，会把内部结构冲掉、卸载后计时器仍触发 —— 改为独立 label 节点。
10. `localStorage` 里的字号/视图损坏时会得到 `NaN` 字号或非法视图 —— 读取时校验并夹紧。
11. 主题在 React 挂载后才写入 `<html>`，首屏闪白 —— 改为 `main.tsx` 渲染前写入。
12. 整行上移时选区偏移公式在行长不等时算错 —— 修正并补测试。
13. 拖动文件离开窗口时遮罩不消失、双击预览定位精度、复制到剪贴板无 `navigator.clipboard` 时的降级等小问题。
14. 项目缺 `index.html`，`vite build` 直接失败 —— 已补。

## 列表与公式（第二轮补全）

### 列表

- 三种无序标记 `-` / `*` / `+`、两种有序标记 `1.` / `1)`、任务项 `- [ ]` / `- [x]`，都能在工具栏下拉菜单里互相转换。
- **嵌套**：`Tab` / `Shift + Tab` 按层升降（列表内自动走一层，普通段落仍是两空格缩进）；回车继承当前层缩进与标记。
- **编号**：回车自动 +1；「重新编号」按钮（`Ctrl+Shift+N`）按嵌套层级重排整块，空白行处重新从 1 开始。
- **退出**：空列表项上回车先升一层，已在最外层则退出列表；行首 `Backspace` 直接去掉列表标记，保留正文。
- **整项操作**：上移 / 下移 / 复制 / 删除会把子项一起带走，不会拆散嵌套。
- 预览端补齐 Tailwind preflight 清掉的列表样式：`disc → circle → square`、`decimal → lower-alpha → lower-roman`，任务项复选框与文字对齐。

### 公式（KaTeX）

- 定界符：行内 `$…$`、`\(…\)`；行间 `$$…$$`、`\[…\]`；行内嵌 `$$…$$` 也认。
- 环境：`\begin{align|aligned|gather|equation|multline|split|cases|array|matrix|pmatrix|bmatrix|vmatrix|smallmatrix…` 直接当块级公式渲染，支持嵌套同名环境。
- 内置宏：`\R \N \Z \Q \C \eps \dd \abs{} \norm{} \set{} \ceil{} \floor{} \and \or`，**渲染与规范检查用同一份宏表**，不会出现“能渲染但被报错”。
- 工具栏「行间公式」下拉可直接插入 `$$`、`\[ \]`、`aligned`、`cases`、`pmatrix`、`equation` 模板。
- 源码高亮认得 `\(…\)`、`\[…\]`、`$$` 多行块与环境名；规范检查也会对 `\(…\)` 内的公式做语法/非数学内容检查，并在公式未闭合时给出「缺少 \end{…} / \] / $$」提示。
- 公式渲染失败时降级为等宽源码（红字），不会整块消失。

`src/mathre.ts` 成为定界符与环境的唯一来源：渲染器、语法高亮、规范检查三处共用，避免判定不一致。

## 公式规范修正与 OI 增强（第三轮）

### 修掉的公式误报

- `$\mathrm{lca}(u,v)$`、`$\operatorname{lca}(u,v)$`、`$\text{ans}$` 都是合法写法，
  不再报“英文单词不应写入 LaTeX”。规范检查现在只提醒**裸写**的英文词：
  `$lca$`、`$lca(u,v)$` 会被排成变量连乘，应改用 `\operatorname` / `\mathrm` 直立排版，并提供一键修复。
- 构建改走 `esbuild.charset = "ascii"`：KaTeX 词法正则含 U+202A–U+D7FF 等 Unicode 范围，
  之前会被写进单文件 HTML 的字面字符，经某些平台转码后损坏成
  `Range out of order in character class`，导致所有公式一起报错；现在产物里是 `\\u202A` 形式的转义，不再怕转码。

### 按「OI 题解工作台」方向补的功能

- **分栏可拖动**：编辑/预览之间的分隔条可拖（25%–75%），比例会被记住。
- **导出菜单**：Markdown / HTML 网页 / 打印为 PDF（浏览器打印），HTML 带公式编号与代码行号样式。
- **题解模板库**：标准 / 图论 / 动态规划 / 数据结构 / 数学证明 / 复杂度片段，顶栏「模板」一键插入。
- **公式助手**：行内公式菜单新增分式、根号、求和、连乘、积分、极限、组合数、`\operatorname{}` 函数名；
  行间公式在预览中自动编号 (1) (2) (3)…
- **代码块增强**：行号列（与代码严格同高对齐）、折叠/展开按钮，原有按语言高亮与复制保留。
- **状态栏**：字数之外增加字符数与预计阅读时长。
- **专注模式**：`Ctrl+Shift+F` 或顶栏「专注」隐藏顶栏与状态栏，`Esc` 退出。

尚未做（建议下一期）：多文档管理与历史版本、算法图示绘制（树/图/线段树导出 SVG）、AI 润色与公式检查。

## 第七轮（PDF 公式转 Markdown/LaTeX + 待补定位）

- **否定图片回填**：上一轮“把公式裁成图片贴回原位”的做法被废弃。导入结果里不允许出现公式图片，全部是可编辑、可搜索的 LaTeX 源码。
- **识别管线（纯本地、无后端）**：先在文字层里检测公式空位（行内间隙 + 行首/行尾留白），再用 PDF.js 渲染页面裁出对应区域；对区域做连通域分割，逐字与 KaTeX 字体模板（数学斜体 / 直立体 / Size1 / Size2 多档）做二值膨胀覆盖匹配，用基线位置判上下标，分数线单独识别成 `\frac` 并用局域基线处理分子分母内部的脚本；`log`、`lca` 等直立算子名会还原为 `\operatorname{...}`。
- **宁可失败也不硬猜**：单字形匹配低于阈值、整体置信度不足、或同一原子被迫拼出第三组上下标（必然触发 KaTeX 双重脚本报错）时，整条公式判失败，用 `$\square$` 占位并计数，绝不输出似是而非或语法非法的 LaTeX。
- **真实样本结果**：用户提供的 `solution.pdf`（8 页，Typora/MathJax 矢量公式）共 305 处公式转成 LaTeX、14 处占位待人工补；预览中 KaTeX 零报错，文档里无任何 `<img>` 公式图。
- **待补定位**：状态栏会显示“X 处公式待补”，点一下（或在命令面板搜“待补”）就依次选中每一处 `$\square$`，补完一处跳下一处，不用全文人肉搜索。
- **顺手清理**：删除公式图片的残留样式与调试钩子；大算子与下置界限不再被误合并成一团，∑/∏ 增加多档字号模板。


## 第八轮（匿名 AI 升级 + AI / 编译联动）

- **默认 AI 切换为 Kilo AI Gateway 匿名免费模型池**：不需要注册账号、不需要 API Key；启动时读取公开模型目录，自动挑选可匿名调用的 `:free` 模型，优先代码与推理模型。官方文档说明匿名免费模型按 IP 限流（约 200 次/小时），共享网络可能共用额度。
- **双通道容灾**：Kilo 请求在拿到回答流之前遇到网络错误或 HTTP 错误，会自动回退到 Pollinations 旧匿名通道；已经开始输出后不切换，避免把两段回答拼在一起。两条公共服务都不可用时会明确报错，不会伪装成功。
- **AI 与编译结果联动**：运行结果面板的 AI 分析入口不再只对编译/运行错误开放；运行成功后也可以把代码、stdin、stdout、stderr、编译日志一起交给 AI 检查结果与潜在边界问题。
- **AI 代码审查**：光标位于 C++ 代码块时，状态栏新增「AI 审查」，检查算法正确性、不变量、边界、溢出、未定义行为、复杂度和常数，并要求模型区分确定问题与推测。
- 保留原有 AI 讲解、题解润色、全文上下文问答、生成测试数据、生成对拍器、分析反例、结果回填等能力；自备 API Key 的服务商配置仍可用。

## AI × 编译联动增强

- 免费 AI 默认使用 Kilo Gateway 的公开免费模型目录，自动选择标记为 free 的模型；目录不可用时使用备用模型，并在主通道失败时尝试 Pollinations 备用通道。免注册、免 Key，但免费服务可能限流、调整模型或暂时不可用。
- 编译结果不再只在报错时交给 AI：运行成功、答案不一致、编译错误、运行时错误都可以携带代码、stdin、stdout、stderr 与编译日志分析。
- A/B 对拍可以把两份代码、同一输入和两边输出一起交给 AI 分析。
- AI 分析结果可提取完整 C++ 修复版，回填运行框后重新编译；回填前会检查是否像完整 C++ 程序，不会自动覆盖文档源码。
- 批量验证的失败项会把期望输出与实际输出一起交给 AI。
- 命令面板新增「AI 审查全文 C++ 代码」和「AI 审查整篇题解」，分别检查代码正确性/边界/溢出/复杂度，以及题解证明/复杂度/边界/表达完整性。

## 自动部署

`.github/workflows/pages.yml` 在 GitHub Actions 上执行构建并发布 `dist`。本机不需要 npm。免费 AI 与在线编译均需要浏览器联网，且依赖第三方服务的实际可用性。
